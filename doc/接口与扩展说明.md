# 接口与扩展说明

## HTTP 入口

运行时 OpenAPI：`http://127.0.0.1:8000/docs`。除演示学员列表、身份选择和管理员登录外，业务接口均要求 `Authorization: Bearer <token>`。

| 路径 | 用途 |
| --- | --- |
| `GET /api/v1/demo/students` | 获取允许体验的预置学员 |
| `POST /api/v1/auth/demo` | 用 `user_id` 选择预置身份，返回短期令牌 |
| `POST /api/v1/auth/admin` | 管理员账号密码登录 |
| `GET/POST /api/v1/conversations` | 列表或创建本人会话 |
| `GET /api/v1/conversations/{id}` | 原始消息、任务、执行状态与程序生成的操作回执 |
| `POST /api/v1/conversations/{id}/messages` | 保存消息并创建异步执行；重复 `request_id` 返回原记录 |
| `POST /api/v1/conversations/{id}/messages?wait=true` | 共用执行链，等待并返回完整回复，供非流式调用 |
| `GET /api/v1/runs/{id}/events?after=0` | SSE 事件；用事件 ID 游标恢复读取，不重复办理 |
| `GET /api/v1/me/orders,refunds,tickets,cohorts` | 本人业务查询，每个资源使用各自路径 |
| `GET /api/v1/me/tickets/{id}` | 本人工单与公开记录 |
| `POST /api/v1/me/tickets/{id}/messages` | 明确补充说明，要求 `operation_id` |
| `GET /api/v1/admin/education/{kind}` | 查询学员、课程、班次、订单、学习、退款、工单；分页参数 `page,size,q` |
| `GET /api/v1/admin/learning/{user_id}/{cohort_id}` | 指定报名学员的详细学习进度 |
| `GET /api/v1/admin/tickets/{id}` | 含内部备注的工单详情 |
| `POST /api/v1/admin/tickets/{id}/messages` | 公开回复或内部备注；`close=true` 公开回复并结单 |
| `POST /api/v1/admin/refunds/{id}/review` | `decision=approve/reject`，必填说明和操作标识 |
| `GET/POST /api/v1/admin/knowledge` | 查询或新增 FAQ/文章 |
| `PUT/DELETE /api/v1/admin/knowledge/{id}` | 按版本修改；仅草稿允许删除，其余下架 |
| `GET /api/v1/admin/knowledge-search?q=...` | 预览已发布内容检索结果 |
| `GET /api/v1/admin/audit` | 查询最近操作记录 |

消息示例（字段均为示例，不含真实凭据）：

```json
{
  "request_id": "client-generated-unique-id",
  "content": "请查询这个订单",
  "business_object": {"kind": "order", "id": 123}
}
```

`business_object` 可省略，支持 `order` 和 `cohort`。服务端按当前身份重新读取对象，不能通过传入内容冒充其他学员的订单。客户端身份信息不进入模型可填写的工具参数。

SSE 事件包括 `delta`、`tool_start`、`tool_result`、`tool_error`、`operation_result`、`done`、`error` 和 `interrupted`。执行先保存再返回编号；断开事件流不取消业务，重新获取会话后可接回运行中的事件。

## 扩展点

- 教育业务：实现 `EducationPort`，或在 `ReferenceHTTP` 后增加其他 HTTP 服务。新业务用例先在教育端实现规则和事务，再包装 MCP 工具。
- 知识检索：实现 `KnowledgeSearchPort.search` 并保持来源、版本和正文片段契约。当前为关键词适配器，无向量库依赖。修改已发布知识即时生效。
- MCP：`mcp_tools.py` 声明工具，`agent.py` 的 `ALLOWED` 是显式安全白名单。新增工具需要注册及验证；内容新增无需修改 Agent。写工具必须加入写入策略并保证幂等。
- Agent：通用 LangGraph 循环与 SQLite 检查点；任务信息位于独立 tasks 表。模型不直连业务数据库，不选择调用身份。
- 存储：新应用使用 SQLite WAL 适配器，教育数据在 MySQL。需要多实例时，先替换共享存储与执行协调，不能简单增加 worker 数。

当前选择 MCP Python SDK 1.x 并在 lock 中锁定版本，避免与 2.x 的重命名和 HTTP API 差异混用。内部 MCP 工具使用服务器签发的短期能力令牌，模型看不到该参数；访问工具需要有效令牌和当前任务状态。

## 业务状态

- 退款：待审核 → 驳回，或待审核 → 模拟退款完成。申请与实际模拟退款分别反馈，客户端不指定金额。
- 工单：待处理 → 处理中 → 已关闭。公开回复与内部备注分开；学员不读取内部备注，关闭后不再补充。
- 任务：激活、暂停、完成、取消；查询插入时保存办理信息，查询完成后恢复最近暂存任务。

数据库事务内幂等记录解决业务重试；新应用的工具回执解决图节点重放。应用强制终止后，租约到期再由单实例恢复同一执行 ID。自然语言办理诉求判断仍有模型不确定性，通过独立审核、业务约束、原始消息与回执追踪降低风险，不宣称绝对无误。
